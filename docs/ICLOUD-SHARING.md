# Horme 0.3.0：別々のApple Accountでデータを共有

## 使い方

1. 両方の端末をこの版に更新する。iCloud用のApple Accountはそれぞれのままでよい。
2. 片方のHormeで「設定とデータ」→「データを共有する」。件数を確認し「統合して同期する」。
3. Appleの共有画面から、もう片方のApple Accountを「変更可能」で招待する。
4. もう片方で届いたiCloud共有リンクを開く。Hormeに表示される件数を確認して統合する。

ここで共有するのはタスク・アイデア・手順・メモ・完了状態・取り組み中の情報を含むデータ一式。TestFlightのインストール招待とは別の招待であり、Hormeの会員登録は不要。

参加時は両方のデータを追加して統合する。同じIDで内容が異なる項目はコピーとして両方残す。既存データを題名だけで同一視して削除しない。開始前のバックアップは「設定とデータ」から書き出せる。

入力はまず端末に保存し、オフラインでは変更を保持する。アプリが手前にある間の定期更新、起動・復帰、接続回復、CloudKitの通知で再同期する。バックグラウンド通知や即時反映はOS・通信状況に依存する。「今すぐ同期」も利用できる。

## Apple側で一度だけ行う設定

Bundle IDは既存の `io.github.reiji55.threedays` を引き続き使用する。

1. [Apple DeveloperのIdentifiers](https://developer.apple.com/account/resources/identifiers/list)で対象のApp IDを開く。
2. iCloudを有効化し、**Include CloudKit support** を選ぶ。
3. iCloud Containerとして **`iCloud.io.github.reiji55.threedays`** を作成・関連付けする。説明はHormeでよい。
4. **Push Notifications** も有効化して保存する。通知許可ダイアログのためではなく、変更を知らせるサイレント通知に使用する。
5. [CloudKit Console](https://icloud.developer.apple.com/)で上記コンテナを開く。
6. **Development** 環境のSchema / Record Typesで **`HormeItem`** を作り、**`payload`** という **Bytes** 型のフィールドを追加する。アプリはレコード変更取得APIを使うので独自の検索インデックスは不要。
7. Schemaの **Deploy Schema Changes** でProductionへ反映する。TestFlight版はProduction環境を使用する。利用者のタスクをConsoleに入力する必要はない。

記載の画面名はApple側の言語設定によって異なる。[Apple：capability設定](https://developer.apple.com/help/account/identifiers/enable-app-capabilities/)、[Apple：CloudKit共有](https://developer.apple.com/videos/play/tech-talks/10874/)。

## 保存と競合の扱い

- 元の `Application Support/ThreeDays/notebook.json` を読み取り、新しい `horme-state.json` に移行する。元ファイルは残す。新ファイルが壊れた場合に古いデータへ自動的に巻き戻すことはしない。
- データ本体、端末ID、同期先、未送信の変更を一つのファイルへ原子的に保存する。再起動で未送信変更が消えない。
- CloudKitのprivate/sharedデータベースとzone sharingを使用。招待はprivate・read/writeのみで、公開リンクとして一般公開しない。
- タスク・アイデアごとにレコードを分け、項目ごとの論理時刻と端末IDで統合する。別の項目への変更は両方を残し、同じ項目の競合は時刻・端末IDによる決定的な順序で解決する。同時編集した文章の意味的な合成はしない。
- 手順はIDごとに統合する。削除記録を保持し、古い端末の編集による削除済み項目の復活を防ぐ。明示的な取り消し・バックアップ復元は新しい変更になる。
- 他端末から変更を受け取った際は、端末の直前の内容を `before-sync.json` に残す。これは直前の一回分で、無期限の編集履歴ではない。古い全体スナップショットのUndoで他端末の変更を消さないよう、リモート変更の受信時にUndo履歴をクリアする。
- 共有参加前は `before-sharing.json` に保存する。設定画面から各バックアップを書き出して内容を確認できる。同期を解除してもクラウドのデータは削除しない。
- 開いたままの編集画面は、本人が編集した項目だけを最新のタスクへ反映する。別端末でタスク全体が削除された場合は勝手に復活させない。
- iCloudアカウントが変わった場合は以前のデータを新しいアカウントへ自動送信しない。共有解除・権限喪失・容量不足でもローカルデータを残す。
- バックアップの「置き換え」は同期先にも反映するため、取り込み確認に明記する。

## 初版の範囲と検証

一つの共有データ一式に接続する個人利用向けの実装。複数の共有先を切り替える管理画面、担当者、通知の催促、Web版、過去の全変更履歴は含めない。

全件取得はCloudKitのページを最後まで処理し、不正なレコードを無視して成功扱いにしない。保存は変更タグを確認し、競合時に再統合する。私有・共有データを一般公開用データベースへ保存しない。将来データが増えた場合は永続化した変更トークンで増分取得へ置き換えられる。

自動テストは旧データ移行、オフライン変更、項目・手順の統合、削除、Undo、同一項目の競合、再起動後の未送信変更、破損データ保護を対象とする。署名なしシミュレータでは本物のiCloud共有を検証できない。配布前のビルド確認と、配布後の異なるApple Accountの実機2台による確認を区別して記録する。

実機では、招待の冷起動・起動中の受信、両方向の追加/完了/編集/削除、機内モード中の同時変更、再起動後の送信、共有解除後のデータ保持を確認する。
